# Project history and context

Summary of the Claude chats and projects exported on 2026-11-12 (Jul 31 – Nov 4 2026), so future work starts from what was already decided. The chats are in Russian; this summary is English. Details come from automated summaries of very long chats, so treat exact numbers as approximate and check the code or the place before relying on them.

## Current direction (as of Nov 4)

**Auto Gladiators-style anime auto-battler, published as a new experience.** It replaces every earlier concept below. Reference data: `AutoGladiators_catalog.md` (Dota 2 custom game v3.16 KV files: 12 styles, 150 ability cards, heroes, 96 items, 78 artifacts, runes, traits, territories, PvE creeps).

- 2–8 players (bots fill empty seats), each controls a 100-HP courier in a hub; fights happen in a coliseum arena. Each turn: shop/prep → pairing → automatic 1v1 battle. Top 4 counts as a win.
- Six starting gladiators (parody names): **Narato** (Naruto), **Zazke** (Sasuke), **Koku** (Goku), **Tuffy** (Luffy), **Sound Hashira** (Tengen), **Blood Demon** (Gyutaro). Names of three future heroes are open.
- Map: coliseum hub + arena (`Coliseum_Roblox_v2.glb`), markers under `workspace.Map.Markers`, decoration under `workspace.Dressing`, `MapAmbient`; arenas cloned 8× in code. Keep the old `Map` when importing; set `Lighting.Technology = Future`.
- Nov 4: a Claude Code session built the code in this repo (see `README.md`): pure-Luau seeded combat engine, all catalog data in one `Config`, shop/economy/progression/match logic, bots, server services, client UI and tests. Runes and some catalog effects are not implemented yet.

**Open decisions:** game title, UI language (config text is currently Russian), rig type (R15 placeholders today), publish owner, copied vs fresh place, names for 3 future heroes.

**User-side tasks:** import the coliseum map, gladiator models + animations (with hit-marker events) + VFX, courier model, card/territory icons, portraits, sounds, promo art; then playtest with 2–8 friends.

## Timeline of earlier concepts (all superseded)

1. **Anime AI Arena / "Train Your Anime 2"** (Jul 31 – mid Sep): AI auto-battler. NPC "brain" with patrol AI, kunai combat prototype, HP bars and damage numbers, 9-stat upgrade system (`StatConfig`), vector-blend combat movement (`CombatTactics`), planned "combat genetics" (memory-only genetic fitness pool for bot behaviour). Bot HP fix: `ServerScriptService.BotSpawnerService` sets cloned bots' `MaxHealth`/`Health` to 190 to match players (set in `GameManager`). Lived only in the `.rbxl`, not in Rojo.
2. **Hole Is Mine clone, "Train Your Anime 2.3"** (late Sep – Oct): village hub, per-player islands with guest visits, procedural caves 1–3 with bosses, drill, minions with anime gacha skins (Narato, Zazke, Koku, Tuffy, Nuts, Tengen, Gyutaro), clash mechanic, weapons (Rasengan, Chidori, Kamehameha, Dragon Slayer, Blood Sickles, Sound Blades), paper-style UI (`PaperUI`, `IconAtlas`), 13-step tutorial, roll tickets, worm shop, mobile controls, analytics panel. Dropped after an ad test: ~50 visits, players quitting within 30 s at the tutorial. Leftover before any release of that place: `AdminConfig.OPEN_TO_EVERYONE` was still `true`.
3. **Rat Game-style multiplayer** (late Oct – Nov 3): rat restaurant map and low-poly rat model designed; dropped in favour of Auto Gladiators.

Assets from these (Tengen/Gyutaro animations and VFX modules `ReplicatedStorage.TengenFX` / `GyutaroClashFX`, character models, Anime Eternal Void assets) may be reused.

## Working preferences

- User does modeling, animation and VFX (VFX built in the VFX Studio plugin, not generated by code); the assistant does scripting, balance, placement and Studio assembly.
- Clean `--!strict` Luau, client/server split, no `as Model` casts; code comments were in Russian.
- Changes must be verified in Play mode, with measurements when tuning.
- Tools: Cursor, Rojo, Obsidian; earlier also Roblox Studio MCP (`script_grep` → `script_read` → `multi_edit`, exact tab indentation). When a session gets interrupted, write a hand-off summary first.
- Monetization should not be pay-to-win; mobile/tablet support matters; parody names to reduce copyright risk.
